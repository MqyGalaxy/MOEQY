# MOEQY 内容工作台

工作台是独立的浏览器编辑界面，配合仅监听本机的文件读写服务。编辑对象仍是网站现有 JSON、YAML 和 Markdown，不需要数据库、账号或云服务，也不会随 Astro 生产构建发布。

## 启动

在 `MOEQY` 项目目录执行：

```powershell
npm run editor
```

打开 **http://127.0.0.1:4322/**，保持该终端运行。关闭终端或按 Ctrl+C 停止编辑器。若端口占用，可先设置 `$env:STUDIO_PORT='4323'` 再启动。请使用终端显示的 `127.0.0.1` 地址。

编辑器不启动网站预览。需要查看网站真实页面时，另开终端执行 `npm run dev`；保存后开发服务器会更新，生产网站仍需单独构建和发布。

## 文章

- 进入文章先选择语言；大按钮显示名称、代码与数量，包含草稿和历史文章。列表搜索仅作用于当前语言，按发布时间从新到旧排列；兼容斜杠／短横线日期和可选时分秒，同一时间按路径排序，无效日期置底。
- 选择现有文章修改，或点击“新增文章”。新文章默认使用当前列表语言并设为草稿，不进入公开页面与归档。保存后定位到该文章语言列表；返回语言菜单、切换文章或页面时会提醒未保存修改。
- 新路径使用 `stories/my-first-story` 这样的目录／名称。已有路径只读，根目录的历史 `post-1` 也可以编辑，避免修改历史地址。
- 编辑标题、日期、语言、分类、标签、封面、Markdown 正文；原有未在表单展示的 YAML 元数据与注释保留。
- “显示在该语言文章列表”对应既有 `lang` 行为；关闭时使用 `language` 保留独立页面而不加入语言文章列表。“草稿”则不生成文章页面。
- 封面可选择已有图片或上传图片。留空时继续使用原来的封面映射或默认图。
- 正文工具条可插入标题、粗体、链接和图片。预览为隔离的 Markdown 预览，禁止运行正文脚本、表单与嵌入播放器，不等同于整个网站的页面预览。
- 新增分类的归档入口，以及现有归档超出一页后的分页，会随内容生成。

## 作品

- JSON 信息保存于 `src/data/works.json`；正文仍为 `src/content/works/{id}/{语言}.md`。
- 在语言标签间切换会保留当前输入；最后一次保存同时写入编辑过的所有语言。
- “公开展示”“首页精选”“作品页推荐”独立维护。未公开作品可以先保存不完整译文，公开时必须具备简体中文、英文、日文的名称、分类、简介、按钮文字与正文。
- 使用站内图片路径作为封面与 Logo；访问地址支持站内路径、HTTP(S)。正文从二级标题开始。

## 为国际化准备内容

- `src/data/locales.json` 集中记录语言名称、字典路径与准备状态。当前公开语言为简体中文、英文和日文（`ja`）。日语字典为 `src/data/ja.yml`。
- 文章编辑页通过“查看／管理文章关系”管理译文，不再手填组 ID。点击“新建译文”后明确选择目标语言；只有保存有效正文时才创建文章并与原文关联，取消编辑不会写入空文件。
- “语言与翻译”显示现有 YAML 文案，支持键名／内容搜索、中文原文对照与缺失项统计。保存只更新对应字典；保留其注释和其他结构。
- “准备新语言”可登记 `ko` 等尚未接入的代码，生成 `src/data/locales/{code}.yml`，并开放作品译文与文章草稿编辑。日语已接入，无需再次登记。
- **新增语言处于准备状态，不会自动生成公开页面。** 正式上线时仍需接入 `Lang` 类型、字典载入、路由前缀、菜单／语言入口、canonical、站点地图，以及组件内尚未抽取的固定文案。不要只把配置改为 `live` 就发布。
- 工具不自动翻译文字，也不改写现有活动日期、原文和历史迁移快照。

## 保存、冲突与恢复

- 保存前校验路径、日期、素材及作品双语完整性。已被其他编辑窗口或外部工具修改的文件，会触发冲突提示，当前输入仍保留。先保留需要的文本，再“重新载入”并合并修改。
- 每次真实写入前，旧内容备份到 `.content-studio/backups/{时间-编号}/`，其中 `manifest.json` 记录涉及文件。新建文件记录为 `existed: false`。
- 如需恢复，停止编辑器后按清单把备份中的原文件复制回对应相对路径；对于该次新建的文件，可根据清单移除。备份不写入生产输出，也不纳入版本库。
- 图片上传最多 10 MB，支持 PNG、JPEG、WebP、GIF；写入 `public/images/uploads/` 下的唯一名称，不覆盖已有素材。未引用的上传文件不会自动删除。
- 保存只改变本地源文件；没有删除文章、删除作品、自动发布或远程管理入口。

## 文章关系工作流

- 侧栏“文章关系”先列出文章组和未绑定文章，按组内最新发布时间排序；搜索可匹配组内任一标题、路径或组 ID。选择后只展示这一组，中心节点连接各语言版本，缺失语言显示虚线占位，准备中的语言另行标注。
- 拖动画布空白处平移，使用缩放、适应画布和居中按钮查看节点。节点自动排布，不保存位置。点击文章标题查看摘要并进入编辑。
- 打开候选文章面板，可筛选语言和搜索标题／路径。从文章或组连接点拖线到候选文章，或直接点击候选项“绑定”；后者也适用于键盘和手机。窄屏候选面板使用抽屉。
- 所有绑定、解除和合并先进入画布预览与变更摘要。可以撤销一步或取消全部修改，点击“保存关系”才统一写入。每种语言在一个组中只能有一篇文章，一篇文章只能属于一个组；连接已有组会合并整个组，重复语言会列出冲突文章并拒绝变更，不自动替换。
- 解除绑定只写入 `translationKey: null`，不删除文章、日期或正文；剩下一篇的组仍保留。新组 ID 自动生成，正式关联继续保存在 Markdown frontmatter 的 `translationKey`。
- 关系保存使用同一版本检查、备份和多文件回滚机制。发生并发冲突时保留待保存操作，先确认外部修改，再重新载入处理；失败不会留下半组绑定。

## 历史关联迁移与网站语言切换

```powershell
npm run editor:migrate-relations
```

命令将现有路径规则中的四对中英文文章转为正式绑定（2024 新春活动、2023-08-08、2023-11-10、2025-07-08 公告）。已经一致的绑定会跳过，可重复运行；已有不同关联或明确解除记录会报告冲突，绝不覆盖。实际写入会生成备份。

关系更新只修改 YAML 关联字段，保留原始正文。`src/data/legacy-post-body-hashes.json` 保存经原文件指纹确认的历史正文指纹；仅修改绑定元数据仍复用历史 HTML。不要修改 `legacy-post-hashes.json`、`legacy-post-html.json` 或手工刷新正文基线来绕过检查。

网站语言切换优先使用正式组内已公开译文；已绑定但没有目标译文，或 `translationKey: null` 明确解除时，进入目标语言文章目录。没有正式关联字段的旧文章继续兼容历史路径规则。草稿不会作为公开语言切换目标；准备中的新语言仍不新增公开路由。

## 检查

```powershell
npm run check
npm run build
npm test
npm run verify
```

`scripts/studio.test.mjs` 和 `scripts/article-relations.test.mjs` 在独立临时项目中验证编辑器读写、语言菜单与排序、拖线／按钮绑定、预览与取消、合并冲突、译文创建、并发保护、多文件失败回滚、幂等迁移和语言切换，不修改真实文章与作品。迁移检查对正文未改动的历史文章仍比较历史快照；正文经过编辑的文章则与当前 Markdown 渲染结果比较，历史路由仍全部检查。

本轮检查结果：类型检查无错误、警告或提示；58 项测试全部通过。生产构建 108 页，保留 98 个历史地址、16 篇文章、6 份说明页和 14 条 FAQ；重复运行关系迁移未产生新写入。桌面和 390／320px 手机宽度已检查关系画布、候选抽屉及取消预览，无横向溢出。

## 日语内容维护

日语现已公开：文章菜单、作品语言标签、站点文案和关系画布均读取同一语言登记。历史文章不自动翻译；无日文译文时，网站语言入口进入日语目录。新建日文文章仍使用 `stories/name-ja` 等不含语言前缀的源路径，网站生成 `/ja/stories/name-ja/`。日文文章可以保存为公开内容，翻译组仍由关系工作流维护。

作品的 `text.ja` 与 `ja.md` 已补齐；已启用作品保存时同时校验三种公开语言。共用 UI 文案也已进入三份 YAML 的 `ui` 段。日语固定说明与 FAQ 仍直接维护源 Markdown／JSON，本轮没有增加说明页编辑器。

新增语言改变文件版本：已打开编辑器时，先保留未保存的输入，再用“重新载入”获取最新语言列表。最新回归为 64 项测试、124 页构建与历史迁移检查通过；测试包括日文文章正式保存／关联、无译文回退、日语公开路由、三语言菜单与作品交互。
